01

DNS：互联网的电话簿

把人类友好的域名，翻译成机器能连的 IP 地址。

你输入 hy2.leonyeung.com ↓ DNS 查询 得到 107.173.141.27 ↓ 你的手机连这个 IP

没有 DNS 会怎样？你就得背 IP 地址 —— 每次上百度都要输入 110.242.68.66。

常见记录类型

类型作用例子
A域名 → IPv4 地址hy2.leonyeung.com → 107.173.141.27
AAAA域名 → IPv6 地址→ 2001:db8::1
CNAME别名，指向另一个域名www → leonyeung.com
MX指定邮件服务器@ → route1.mx.cloudflare.net
TXT文本记录（验证/反垃圾）SPF、DKIM
关键点：DNS 不加密任何东西，它只是个「查询服务」，负责告诉你该连哪个 IP。
02

证书：服务器的身份证

证明「这台服务器真的是它声称的那个域名」。

没有证书会发生什么

你的手机连上某个服务器，服务器说「我是 hy2.leonyeung.com」—— 你怎么知道它没骗你？

中间人可以冒充服务器，把你的所有流量偷走。这就是「中间人攻击」。

证书如何解决

🔐
服务器出示证书
证书由受信任的 CA（如 Let's Encrypt）签发，写明「此证书颁发给 hy2.leonyeung.com」
🔍
手机验证签名
检查 CA 的签名是否有效——伪造的证书签不出合法签名
✅
确认身份，建立加密
双方协商出会话密钥，后续数据全部加密传输

证书做两件事

🪪 身份验证

确认服务器不是冒牌货，防止中间人窃听

🔑 加密协商

让双方安全地商定加密密钥，之后的数据都是密文

DNS
查电话簿

得到「去哪里找」——域名对应的 IP 地址

证书
看身份证

确认「是不是真的」——服务器身份是否可信

完整连接流程

DNS 和证书如何配合，完成一次安全连接。

1️⃣
输入域名DNS
你在客户端点击「连接 hy2.leonyeung.com」
2️⃣
DNS 解析DNS
查询得到 IP：107.173.141.27
3️⃣
TCP / QUIC 连接传输层
手机连到 107.173.141.27:30443
4️⃣
TLS 握手 · 服务器出示证书证书
服务器：「我是 hy2.leonyeung.com」，并附上 Let's Encrypt 签发的证书
5️⃣
手机验证证书证书
域名匹配 ✓　签发者可信 ✓　未过期 ✓
6️⃣
协商会话密钥加密
此后所有数据都用这个密钥加密，中间人只能看到密文
7️⃣
开始传输
加密隧道建立完成，可以安全传输数据
记住这个分工：DNS 负责「去哪找」（地址），证书负责「是不是真的」（身份）。两者缺一不可。
04

Hysteria2 是怎么工作的

基于 QUIC 的高速代理协议，专为恶劣网络环境设计。

核心目标

不加隧道： 手机 → 直接访问 google.com 中间设备能看到「你要访问 google.com」→ 可能被阻断 加隧道： 手机 → 加密流量 → 服务器 → google.com 中间只能看到「你在和某个 IP 通信」→ 不知道内容

五个阶段

🌐
阶段 1 · 找到服务器DNS
解析 hy2.leonyeung.com → 107.173.141.27
🔐
阶段 2 · TLS 握手证书加密
QUIC 握手 + 服务器出示 Let's Encrypt 证书 + 协商会话密钥
🔑
阶段 3 · 身份认证
手机发送密码（auth 字段），服务器校验。这是 Hysteria2 自己的认证，跑在已加密的通道内
🎭
阶段 4 · 混淆Salamander
给所有 UDP 包加一层「噪声伪装」，让流量看起来像随机字节，中间设备无法识别协议特征
📦
阶段 5 · 传输数据
请求打包 → 加密 → 加混淆 → 通过 QUIC(UDP) 发给服务器；服务器解开后替你去访问目标网站

三个技术特点

⚡ 基于 QUIC（UDP）

1 次握手就建立连接（TCP 要 3 次）；丢包恢复快，弱网表现远好于 TCP

🚀 Brutal 拥塞控制

按设定带宽强行发包，不管丢包。丢包 10-20% 的网络里仍能跑满带宽

🎭 Salamander 混淆

让 UDP 流量看起来像随机噪声，中间设备无法识别这是代理协议

真实配置对照

地址: hy2.leonyeung.com 端口: 30443 (UDP) 密码: <auth> SNI: hy2.leonyeung.com ← TLS 证书的域名 ALPN: h3 ← 使用 HTTP/3 (QUIC) 混淆: salamander ← 加噪声 证书: Let's Encrypt ← 证明身份
注意代价：Brutal 拥塞控制会占用较多带宽，对共享网络不友好。这是速度换来的。
05

四种协议对比

什么时候需要证书？什么时候不需要？

协议传输层需要 DNS需要证书说明
Hysteria2 QUIC / UDP ✓ 需要 ✓ 需要 速度最快，弱网最优，需真实证书
VLESS + TLS + WS TCP ✓ 需要 ✓ 需要 标准 HTTPS，兼容性最好，可走 CDN
VLESS + Reality TCP ✓ 需要 ✗ 不需要 借用目标网站（如 Cloudflare）的证书伪装
VMess + TLS TCP ✓ 需要 ✓ 需要 老牌协议，兼容性好

为什么 Reality 不需要证书？

普通 TLS： 你的服务器出示自己的证书 → 手机验证 → 不在信任列表就失败 Reality： 你的服务器把手机的握手请求原样转发给 cloudflare.com → Cloudflare 返回它的真证书 → 手机看到「真的 Cloudflare 证书」→ 验证通过 → 中间人看到的也是「你在访问 Cloudflare」

Reality 的精妙之处：技术上没有伪造任何东西。它只是把连接「借道」给了真实的 Cloudflare，让审查者看到的是完全合法的流量。

06

为什么 Hysteria2 走不了 CDN

Cloudflare 能代理什么、不能代理什么。

Cloudflare 免费版支持不支持
HTTP / HTTPS
WebSocket
gRPC		 原始 TCP / UDP 流量
QUIC（Hysteria2）
Reality（需原始 TLS 握手）

结论

🚀 Hysteria2

必须直连（灰云 DNS）。因为它是 UDP/QUIC，CDN 不支持代理

🕵️ VLESS + Reality

必须直连。Reality 需要原始 TLS 握手，CDN 会破坏这个过程

🌐 VLESS + WS + TLS

可以走 CDN（橙云）。标准 HTTPS + WebSocket，CDN 完全支持

DNS 记录中的两种状态

🟠 橙云（Proxied）
流量经过 Cloudflare

隐藏真实 IP、防 DDoS、CDN 加速。适用于网站和 WebSocket 类代理

⚪ 灰云（DNS Only）
仅提供解析

Cloudflare 只告诉客户端 IP 地址，流量直接连服务器。Hysteria2 / Reality 必须用这个

常见误解：「VPN 节点不走 CDN，是不是就不用加 DNS 记录了？」
不是。只要你的域名 NS 托管在 Cloudflare，就必须在 CF 里加 A 记录——否则域名根本无法解析。加记录 ≠ 走 CDN，灰云状态下流量完全是直连的。
