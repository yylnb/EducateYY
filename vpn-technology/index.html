01

VPN 是什么？基础原理

先看一段流量如何从你的设备出发，经由海外服务器访问目标网站，再沿原路返回。

在中国大陆的日常语境里，“翻墙 VPN”常被用来泛指通过境外节点转发网络流量的服务。本文重点介绍这类代理隧道的工作方式；它不一定等同于企业远程接入中定义严格的传统 VPN。

请求方向 [设备 / 应用流量] │ 客户端接管并加密 ▼ [加密隧道] │ ▼ [海外代理服务器] vpn.leonyeung.com 107.173.141.27 │ 代替设备访问 ▼ [目标网站] www.leonyeung.com 198.23.160.61 返回方向 [目标网站] │ 响应 ▼ [海外代理服务器] │ 加密后经隧道返回 ▼ [加密隧道] │ ▼ [设备 / 应用流量]
1
客户端接管流量
客户端可能按规则转发全部流量，也可能只接管选中的应用或目标地址。
2
节点代为访问
海外服务器解开隧道封装，向目标网站建立另一段连接；网站通常看到的是出口服务器的网络地址。
3
响应沿隧道返回
服务器把目标网站的响应重新封装并发回设备，客户端解封装后交给原应用。
隧道不等于绝对隐身：本地网络通常仍能观察到你连接的节点地址、连接时间和流量大小。若目标网站使用 HTTPS，应用数据还会在设备与目标网站之间单独加密；VPN 隧道和 HTTPS 是两层不同的保护。
02

DNS 是什么？

DNS 把方便记忆的域名解析成设备可以连接的 IP 地址。

你要连接代理节点： vpn.leonyeung.com │ DNS 查询（示意） ▼ 107.173.141.27 │ 设备再向这个 IP 和指定端口建立连接 ▼ VPN 节点

访问网站时也会发生类似查询。例如，www.leonyeung.com 可以解析到 198.23.160.61。这里的域名与地址仅用于说明解析关系，不代表实际 DNS 配置。

常见记录

记录用途示意
A把域名指向 IPv4 地址vpn.leonyeung.com → 107.173.141.27
AAAA把域名指向 IPv6 地址返回一个 IPv6 地址
CNAME把一个域名设为另一个域名的别名www.leonyeung.com → leonyeung.com
MX / TXT邮件路由或域名文本信息邮件服务配置、域名验证等
DNS 不负责加密：它回答“这个名字对应哪里”，不负责建立 VPN 隧道或验证服务器身份。DNS 查询由设备还是代理节点发出，取决于客户端的路由与 DNS 设置。
03

证书是什么？

在 TLS 连接中，服务器证书用于证明公钥与某个域名的身份关系。

设备连接 vpn.leonyeung.com 时，服务器可以出示一张包含该域名和服务器公钥的证书。设备会检查证书链是否可信、域名是否匹配、证书是否仍在有效期内等。

1
服务器出示证书
证书把服务器公钥与 vpn.leonyeung.com 等身份信息关联起来，并由证书颁发机构签名。
2
客户端验证身份
客户端校验证书签名链、连接域名和有效期；检查失败时，正常客户端应拒绝或警告该连接。
3
TLS 协商连接密钥
TLS 握手使用证书身份验证及密钥协商等机制建立安全连接，之后的数据由会话密钥保护。
DNS
查地址

域名对应哪个 IP？

证书
验身份

连接到的服务器是否能证明自己对应这个域名？

证书本身不是“加密开关”：它主要参与身份验证。TLS 连接的加密还依赖握手中的密钥协商和后续的数据加密；证书里的私钥不应离开服务器。
04

IP 地址与端口是什么？

IP 用来定位网络设备，端口用来区分设备上提供的不同网络服务。

IP ADDRESS
找到哪台设备

例如代理节点的示意地址 107.173.141.27。

PORT
找到哪个服务

同一台设备可在不同端口监听不同服务，例如 443 或 30443。

域名 vpn.leonyeung.com │ DNS 解析 ▼ IP 地址 107.173.141.27 │ 再指定传输协议与端口 ▼ 107.173.141.27:443 / TCP 107.173.141.27:30443 / UDP

端口属于具体传输协议，因此 TCP 的 443 和 UDP 的 443 是不同的监听端点。端口号本身不会告诉你流量是否加密，也不能单凭端口判断服务器运行的是什么应用。

05

加密与 TLS 是什么？

加密保护数据内容；TLS 则把身份验证、密钥协商和加密传输组合成一套安全连接机制。

以带 TLS 的代理连接为例 应用数据 ↓ 代理协议封装 代理数据 ↓ TLS 握手：验证身份、协商会话密钥 加密后的数据 ↓ TCP 等传输 公网

内容保密

没有会话密钥的旁观者不能直接读懂受加密保护的数据内容。

身份验证

客户端验证服务器身份，减少连接到冒牌服务器的风险。

完整性校验

连接可以检测受保护的数据是否在传输中被篡改。

分清两层：代理隧道保护“设备到代理节点”这一段；HTTPS 的 TLS 保护“设备到目标网站”这一段。即使节点出口能看到目标地址，HTTPS 内容通常仍由浏览器与目标网站端到端保护。
06

TCP 协议和 UDP 协议

它们是常见的传输方式，提供的交付语义不同；UDP 并不自动等于更快。

特性TCPUDP
数据形式连续、有序的字节流一个个独立的数据报
交付保障提供确认、重传和有序交付协议本身不保证送达、顺序或去重
连接机制建立连接后传输不建立 TCP 式连接，开销较轻
常见用途网页、文件传输、远程连接实时音视频、DNS，以及 QUIC 的底层承载
TCP：应用数据 → 有序字节流 → 确认与必要时重传 UDP：应用数据 → 数据报 → 由应用或上层协议决定是否处理丢包

QUIC 建立在 UDP 之上，但会在更高层实现加密、可靠传输和拥塞控制等能力。因此，“使用 UDP”不代表上层一定不可靠；Hysteria2 使用的是基于 QUIC 的传输，而不是把所有 TCP 特性都丢掉。

07

HTTP / HTTPS 原理

HTTP 规定客户端与服务器如何表达请求、返回响应；HTTPS 是受 TLS 保护的 HTTP 连接。

浏览器 ── HTTP 请求 ──→ 网站服务器 浏览器 ←─ HTTP 响应 ─── 网站服务器 HTTPS：在 HTTP 数据外增加 TLS 保护 HTTP/1.1、HTTP/2 常见于 TCP；HTTP/3 运行在 QUIC 上
名称它解决什么问题连接特点
HTTP描述请求方法、路径、标头和响应本身不提供传输加密
HTTPSHTTP 加上 TLS 身份验证与数据保护常见网页连接会验证网站证书

在代理配置里，HTTP/HTTPS 可能是访问网站的应用协议，也可能是代理流量外层使用的传输形式。看到“HTTPS”不能单独推断里面跑的是哪一种代理协议。

08

WebSocket 原理

WebSocket 先通过 HTTP 握手建立连接，再在同一条连接上进行双向消息通信。

客户端 ── HTTP 握手 / Upgrade ──→ 服务器 客户端 ←──── 同意切换协议 ───── 服务器 客户端 ←══ WebSocket 双向消息 ══→ 服务器 wss:// = WebSocket 连接外再使用 TLS 保护

与普通 HTTP 请求响应不同，WebSocket 连接建立后可以由任一端随时发送消息，适合实时通信。它本身不是加密协议：使用 wss 时，TLS 才负责连接的加密和身份验证。

有些代理部署会把代理数据放进 WebSocket，再通过 HTTP 反向代理或 CDN 转发。能否转发取决于中间服务是否支持 WebSocket、路径和超时等配置，并非 WebSocket 一定能通过任何 CDN。

09

gRPC 原理

gRPC 是远程过程调用框架，让客户端像调用本地方法一样请求远端服务。

客户端调用方法 │ 方法名 + 序列化后的请求 ▼ HTTP/2 连接 ─────────────→ gRPC 服务 HTTP/2 响应 / 数据流 ←───── 服务处理结果

gRPC 通常使用 HTTP/2 传输，并常以 Protocol Buffers 定义消息和服务接口。它支持单次请求响应，也支持客户端、服务端或双方持续交换消息的流式调用。

在代理场景中，gRPC 可以作为外层承载方式之一；它不是 VMess、VLESS、Trojan 这类代理协议的同义词。中间反向代理需要正确支持 HTTP/2、gRPC 路由及相关超时设置。

10

VMess 原理

VMess 是 V2Ray 生态中的代理协议，负责客户端与服务端之间的用户识别、请求信息和代理数据封装。

1
客户端准备代理请求
请求中包含用户凭据以及要访问的目标地址和端口。
2
VMess 封装并保护数据
客户端按双方配置生成协议数据；VMess 有自身的数据加密机制，也可再组合 TLS 等传输层保护。
3
服务端验证后转发
服务端识别用户请求，连接目标地址并在客户端与目标之间转发数据。

VMess 不等于某一种底层传输。具体配置可以组合不同传输方式和 TLS 等安全层，客户端与服务端需要在用户凭据、传输参数和安全设置上匹配。

理解重点：VMess 负责代理协议层的用户与目标请求；TCP、WebSocket、gRPC、TLS 等则描述它如何承载或保护连接。实际可用组合以使用的软件及版本为准。
11

VLESS 原理

先看常见的 VLESS + REALITY 组合：REALITY 处理外层 TLS 握手与伪装；VLESS 在连接通过验证后，携带真正要访问的目标地址。

成功的 VLESS + REALITY 代理连接 客户端连接代理服务器 198.23.160.61:443 │ TLS ClientHello 带伪装 SNI：www.cloudflare.com ▼ 代理服务器上的 REALITY 校验客户端参数 │ 通过：返回 REALITY 临时可信证书并建立受保护连接 ▼ VLESS 请求：UUID + 真实目标 vpn.leonyeung.com + 数据 │ ▼ 代理服务器访问真实目标，响应经通道返回 未通过 REALITY 校验的连接会走另一条回落路径： 代理服务器 ── 转发 ──→ 伪装目标 www.cloudflare.com

所以，“伪装成访问 www.cloudflare.com”说的是外层 TLS 握手呈现的站点名和连接特征，不是把代理流量真的发去浏览这个网站。连接到代理服务器后，REALITY 先识别合法客户端；只有验证通过，客户端才在受保护的连接中发送 VLESS 请求，告诉节点真正要访问的目标地址。VLESS 也可以搭配 TLS 等其他传输安全方式，并非每个 VLESS 节点都使用 REALITY。

REALITY 是什么

REALITY 是 Xray 生态中的 TLS 外观与验证机制。合法连接时，客户端验证 REALITY 提供的临时可信证书；若连接没有通过 REALITY 校验，服务端可将流量转发给配置的伪装目标，此时客户端看到的才可能是目标站真实证书。它不是简单复制目标站证书，也不是先建立一次普通网站访问、再把那张证书拿来给代理连接使用。REALITY 与 TLS 终止型中间代理通常不兼容，能否共存要看具体配置和中间服务行为。

记住两种“目标”：SNI 中的伪装站点名用于 TLS 握手外观；VLESS 请求中的真实目标地址用于节点出站访问。两者用途不同，示意域名不代表实际配置。Xray 中 REALITY 可与 RAW、XHTTP、gRPC 组合，不能简单把它和 WebSocket 当成任意可叠加的选项。
12

Hysteria2 原理

Hysteria2 基于 QUIC，使用 UDP 作为网络承载，并通过 TLS 1.3 保护连接。

1
解析节点地址并连接
客户端把 vpn.leonyeung.com 解析为示意地址 107.173.141.27，再通过 UDP 建立 QUIC 连接。
2
建立 QUIC / TLS 安全连接
QUIC 集成 TLS 1.3 握手和连接保护；客户端按配置验证服务端身份。随后客户端通过 HTTP/3 的 /auth 请求认证，成功时服务端返回 233 HyOK。
3
认证并转发流量
认证成功后连接切换到 Hysteria 代理协议：TCP 连接通过 QUIC 双向流转发，UDP 数据报通过 QUIC Datagram 转发；两者不是同一种数据通道。

QUIC over UDP

使用 QUIC 的连接、加密与拥塞控制机制；底层 UDP 网络仍可能丢包或受到限速。

TCP 与 UDP 转发

外层连接使用 QUIC，不妨碍代理协议转发 TCP 流量或 UDP 数据报。

可选混淆

支持的配置可增加 Salamander 混淆；混淆不等于加密，也不能替代 TLS 验证。

速度没有绝对保证：实际表现受线路质量、丢包、拥塞、服务器配置和客户端实现影响。UDP 被网络限制时，基于 QUIC 的连接也可能无法使用。
13

Trojan 原理

常见 Trojan 部署把代理请求放在 TLS 连接中，由服务端凭密码识别用户并转发目标流量。

Trojan 一次 TCP 代理连接 客户端 ── TCP + TLS 握手 ──→ vpn.leonyeung.com:443 客户端 ←── 服务器证书 ────── Trojan 服务器 客户端验证证书中的域名、信任链和有效期 │ TLS 加密通道建立 ▼ 客户端 ── Trojan 密码 + CONNECT + www.leonyeung.com:443 ──→ 服务器 服务器验证密码；通过后连接 www.leonyeung.com:443 │ 客户端 ←════════ TLS 内双向转发数据 ════════→ 目标网站

Trojan 连接里有两次不同方向的验证：TLS 握手时，客户端检查服务器证书，确认自己连到预期的 vpn.leonyeung.com；TLS 建好后，客户端才在加密通道里发送 Trojan 密码和 CONNECT 目标，服务器检查密码，再替客户端连接 www.leonyeung.com:443。证书不是代理密码，密码也不能代替证书验证。

Trojan 的传输方式、UDP 转发能力及与反向代理的兼容性会因实现和配置而异，不能仅凭协议名称推断。它与 VMess、VLESS 一样，最终都由服务端替客户端向目标地址发起连接。

四种协议对比

对比时要同时看代理协议、承载方式和连接保护，不能只看一个协议名称。

协议常见承载方式常见认证连接保护理解重点
VMess TCP、WebSocket 等，依实现配置 用户 ID 等协议凭据 按配置使用协议加密；也可叠加 TLS V2Ray 生态中的代理协议，组合方式较多
VLESS TCP、WebSocket、gRPC 等，依配置 通常为 UUID 常组合 TLS 或 REALITY；具体取决于配置 协议精简，安全性要连同外层机制一起评估
Hysteria2 QUIC over UDP 密码等认证信息 QUIC 集成 TLS 1.3 面向 QUIC 传输，可代理 TCP 与 UDP
Trojan 常见为 TLS 上的 TCP 连接 密码 常见部署依赖 TLS 保护 验证方式、UDP 能力与承载取决于具体实现

能不能走 CDN？

这不是单由 VMess、VLESS 或 Trojan 名称决定的。基于 WebSocket 或 gRPC 的配置，只有在中间服务支持相应协议、路由和连接时长时才可能转发；Hysteria2 使用 UDP/QUIC，需要中间服务明确支持相应 UDP 转发。TLS 终止、REALITY 验证和端到端连接也可能互相冲突。

VMess / VLESS / Hysteria2 / Trojan

再看外层组合
TCP / UDP / TLS / WS / gRPC

连接如何承载、加密，以及沿途网络是否支持这种组合？

选择时的顺序：先确认客户端和服务端都支持，再确认网络能否连通、认证与证书验证是否正确，最后才比较特定线路上的速度和稳定性。协议名称本身不构成速度或安全保证。
